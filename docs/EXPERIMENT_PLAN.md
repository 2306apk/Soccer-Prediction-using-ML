# Experiment Plan and Handoff Contract

## Rule zero: keep two tracks separate

**Paper reproduction track:** `paper_F1`, `paper_F2`, `paper_F3`. These reproduce the original source and are not safe as genuine pre-kickoff inputs because the released values use end-of-season ratings/statistics and match minutes.

**Primary prediction track:** `historical_only` and `historical_only_extended`. These use prior match results, Elo and historical venue performance only. They are the default feature groups for all headline model comparisons.

**Sensitivity track:** `historical_plus_ratings_sensitivity`. These add prior-season player ratings tied to the target fixture's recorded starting XI. Do not call this strictly leakage-free unless a timestamped source confirms that the XI was known before kickoff.

## Experiments

| ID | Feature group | Models | Question |
|---|---|---|---|
| E0 | Paper F1, F2 and F3, evaluated separately | Original GDA/SVM/Softmax/NN variants where feasible | Can we reproduce the paper's reported comparison? |
| E1 | `historical_only` | Polynomial SVM baseline | What is the performance of the historical-only feature set? |
| E2 | `historical_only_extended` | Same tuned SVM and comparable baseline | Do longer/multiple form windows help? |
| E3 | Best historical feature set | Random Forest, Gradient Boosting, HistGradientBoosting | Do tree ensembles outperform SVM? |
| E4 | `historical_plus_ratings_sensitivity` | Best individual model(s) | How sensitive are results to lineup-dependent prior-season ratings? |
| E5 | Selected historical feature set | Soft Voting, only if validation supports it | Does combining models improve validation performance? |

For ablation studies, change one group at a time. Do not tune by repeatedly looking at the final test score.

## Evaluation protocol

1. Keep rows sorted by date for feature construction.
2. Reproduce a paper-style random 80/20 split as a separate comparison, where feasible.
3. Also use a temporal split: earlier seasons for training, a later season for validation, and the latest held-out season(s) for final testing.
4. Fit imputation, scaling, feature selection and model parameters inside training folds using a scikit-learn `Pipeline`.
5. Report accuracy, macro F1, class-wise precision/recall/F1, draw precision/recall, confusion matrix and train/validation gap.
6. State the exact split, seasons, feature group and hyperparameters for every result.
7. Treat 58.89% as the paper's reported reference, not a guaranteed result or an accuracy target to force.
